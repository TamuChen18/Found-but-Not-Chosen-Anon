# Final primary numbers: provenance

Final primary protocol: strict offline postprocess with E4 off and E2b off (`freeze_strict_matched.py --keep_multi_pred`),
hard0 structural filter, exact-JSON majority over normalized workflows (BoN one vote per call, tree pools one vote per
unique solution text), tie -> smallest `candidate_id`. 183 test tasks.

## Paper transcription corrections

- Seed-sensitivity table (GPT-4o-mini), Winner share column: the paper draft listed CoT-tree fixed seed .810, CoT-tree
  no seed .770, MO-Tree fixed seed .550, MO-Tree no seed .580. These came from two-decimal values in an interim summary
  (0.81 / 0.77 / 0.56 / 0.58) padded to three decimals, plus a transcription slip (0.56 -> .550). No result was
  recomputed and no experiment changed. The values in `artifacts/mini_noseed_trees_full/noseed_trees_summary.csv`
  (`win_share_mean`, protocol `e2b_off`) are .806 / .769 / .555 / .583; the no-seed values equal the pool-statistics
  table (.769 / .583). BoN rows (.925 from `artifacts/mini_noseed_bon_full/no_seed_bon_summary.csv` run `seeded_rerun`,
  .881) were already correct.

- Pool statistics (Qwen3.5-9B prompt-matched control), run-level prompt-matched table and the corresponding text
  (twice): unique valid workflows per task 4.06 -> 4.05. The value is 742 / 183 = 4.0546; 4.06 came from rounding the
  three-decimal value 4.055 in `artifacts/final_primary/fig1/fig1_diversity.csv` again. No result was recomputed.

## Release reproduction

The released results were regenerated with `scripts/reproduce_all.sh` in a clean environment (fresh Python 3.12
virtual environment with `requirements.txt` only, release code + data package, DisasterBench_Open cloned at
`408672bf0da489d94e6245900a87ec913b3d69f9`) and compared file by file with the research repository:

- identical: every bundle, table, CSV and JSON result except those listed below;
- `usage.json` of the judge / verifier / selector steps: zero API calls (offline replay);
- PDF figures: identical except the creation date in the research copies (the release sets `SOURCE_DATE_EPOCH`);
- `final_primary/breadth_{medium,orig}_manifest.json`: run paths renamed to `runs/...`;
- `final_primary/verifier_failure_modes/{per_case,summary}.csv`, column `chosen_wrong_param_acc` / `param_acc`
  (not reported in the paper): 2.9% -> 1.1% of the 175 false overrides pass the Parameter check, because the pinned
  evaluator also compares step outputs (3 chosen workflows differ from the reference only in an output key).

Answer extraction from raw completions (`isolate_answer`, `extract_answer_from_model_completion`) keeps the version
that produced the stored candidate answers (`src/evaluators/evaluators.py`); with the more lenient pinned upstream
extraction, the offline re-extraction steps (budget curves, vote multiplicity, unique-text selector, BoN online
postprocess audit) would parse a few dozen Qwen CoT-tree completions differently and no longer reconstruct the
stored pools. On all 8,460 distinct (task, workflow) pairs of the evaluated bundles, Exact Match and the Tool /
Parameter / Dependency checks of the pinned evaluator equal those of the evaluator used during the study.

`artifacts/vote_loss_audit_final/audit_sample_final.csv`: five rows (mini-Five-153, mini-Five-181, qwen_b1-BoN-41,
qwen_b1-CoT-122, qwen_b1-Five-113) were marked `assistant-review; author to confirm` in the research copy. The
authors confirmed them before release; their labels are unchanged (they equal the LLM labels), and only `reviewer`
(now `author`) and `label_source` (now `llm+author-review:confirm`) were updated.
